# 简体中文全文译稿 PDF

仅当用户需要译稿时读取并执行本流程。目标是生成一份内容完整、术语准确、可检索且可核验的中文 PDF；不承诺逐像素复制原排版，但要保留论文结构和图表对应关系。

## 翻译范围与保真

默认翻译题名、摘要、关键词、正文标题与正文、图注、表题与表内自然语言、脚注、致谢和附录。参考文献的作者、出处、卷期页码、DOI、URL 和正式题名通常保持原文，以免破坏检索；若理解需要，可在不改动原条目的前提下补充中文题名。

保持以下内容不变：

- 公式、变量、上下标、编号和数学关系；
- 图像本身、表格数值、单位、引用编号及交叉引用；
- 代码、命令、文件名、数据集名、模型名和 URL；
- 人名、机构名及尚无稳定中文译法的专名，必要时加中文说明而非强译。

不要删减、扩写、润色成新观点，或用讲解替代翻译。原文疑似有误时忠实翻译，并用清楚标记的译者注说明，不暗中修正。

## 术语策略

开始全文翻译前先识别论文领域、子领域及核心术语，建立轻量术语表。术语选择按以下优先级判断：

1. 该专业领域通行的简体中文译法；
2. 权威教材、标准、专业学会或高质量中文论文中的稳定用法；
3. 结合定义、公式和上下文得到的准确直译。

首次出现时采用“中文（English）”，之后保持一致。一个英文词在不同上下文含义不同时允许采用不同译法，但要避免无理由漂移。对没有公认译法、直译易误导或作为技术品牌使用的词，保留英文并给出简短解释。

机器学习、统计、医学、生物学、物理等领域的近义术语不可凭日常含义替换。遇到影响方法或结论理解的歧义，查阅权威来源验证；仍不能确定时保留英文并注明。

## 版面重建

优先使用能稳定生成 Unicode 中文和嵌入字体的文档/PDF 工具。译稿应包含：

- 清晰的中文题名和原文身份信息；
- 可辨认的章节层级、段落、列表和页码；
- 原图，及与正文一致的图号和中文图注；
- 可读的表格；必要时因宽度改为横向页，但不截断数值；
- 字体清晰的公式及原编号；
- 可点击或至少可识别的 DOI/URL（工具支持时）。

若无法在合理时间内精确复刻双栏版式，可采用结构清楚的单栏译稿。优先保证内容完整、公式图表清晰和交叉引用正确，而非追求外观复制。

扫描 PDF 应先 OCR，并抽查容易误识别的符号、上下标、负号、希腊字母、表格小数点和参考文献编号。OCR 质量不足以可靠翻译时，说明受影响页码并请求更清晰文件。

### 中文混排、字体与列表的默认设置

中文正文不能沿用英文按空格断词的两端对齐。已复现的失败场景：ReportLab `TA_JUSTIFY` 未配置 `wordWrap="CJK"` 时，长中文片段被当成一个词，剩余宽度被分配给少量英文空格，使 `MedMCQA … 和 … HealthBench`、模型版本号和项目符号之间出现超过十个汉字宽的大洞。文字可提取、页数正确、没有空白页，仍然可能严重失排。

- ReportLab 正文默认使用 `alignment=TA_LEFT, wordWrap="CJK"`。表格单元格、图注、提示词自然语言和列表必须显式继承这两个设置，不从旧的英文两端对齐样式继承。其他引擎同样启用中文断行，并避免拉伸中英混排的词间空格。
- 优先复用 [`../scripts/cjk_layout.py`](../scripts/cjk_layout.py) 的 `make_cjk_styles(regular_font, bold_font)`，调用前注册实际可用的静态 Regular 和 Bold 中文字体。返回 `body`、`cell`、`caption`、`prompt`、`bullet` 样式；真正代码另用保留缩进的预格式文本，不将其当作正文或数学记法转换。
- 不要直接把未实例化的可变字体 `*-VF.ttf` 当作常规字重。本次 `NotoSansSC-VF.ttf` 实际嵌入成了 `NotoSansSC-Thin`，使正文异常纤细。改用静态 Regular/Medium 字体；如必须用可变字体，先导出明确字重的静态实例，再核实最终 PDF 的字体名、字重和可读性。不能只看注册别名 `CJK`。
- 注册中文字体家族的 normal/bold 映射，确保 `<b>` 不意外退回西文字体。提供的 helper 未提供真正斜体；确需斜体时另行配置支持该字形的字体，不能把别名当作斜体证据。
- 每个列表条目单独使用 `Paragraph(..., bulletText="•")` 或 `ListFlowable`；不要把多条项目拼为一个带 `<br/>•` 的两端对齐段落。检查条目缩进、粗体起始词、跨页条目和连续编号。
- 不能靠删去所有英文空格、强塞空格或手动逐行 `<br/>` 修补正文；保持源数据名称、数字与单位、模型版本、接口标识符和自然段的完整性。

修改生成器后，先用实际目标字体排一页混排样张：包含长中文句、多个英文数据集名、`Claude 3.5 Sonnet v2`、百分数、引用上标、项目符号和长接口名。确认正文、表格单元格、图注和提示词框均无异常拉伸后，再生成全文。样张通过不代表全文免检。

## 算法、公式与文本层的安全流水线

算法行、公式说明和普通正文必须共用同一套安全的内联记法处理，不得让算法框绕过验证。若渲染器以 HTML/XML 风格标签表达上下标，处理顺序固定为：

1. 从未转义且已识别为数学内容的文本片段识别受支持的记法，并转换为受控的内部 `<sub>`/`<super>` 标记；普通代码、接口名、文件名和 URL 中的下划线不参与转换；
2. 对整段文本执行转义；
3. 仅反向恢复精确匹配的白名单 `<sub>`、`</sub>`、`<super>`、`</super>`；
4. 再交给段落或算法行渲染器。

禁止在转义之后再运行会生成标签的转换函数；否则 `<sub>` 会进入文本层并显示为字面量。也禁止为了恢复下标而解码任意 HTML，这会把源论文文本当成可执行标记。算法行和正文都必须调用同一个白名单入口。

每次新增或修改 PDF 生成器后，至少用以下样例同时测试正文样式和算法样式：`q_i(x3)`、`λ_i(x1)`、`x_0`、`x₀`、`x̂`、`R_succ`。同时检查渲染图和重新提取的文本：

- 下标必须在视觉上真正降低，不能出现字面 `<sub>`、`&lt;sub&gt;` 或内部占位符；
- `x₀` 应转成真正下标；
- 组合字符 `x̂` 只有在目标字体的渲染和 ToUnicode 文本映射都正确时才可保留；失败时先换覆盖该字形的字体或数学渲染方式，仍不能可靠输出时才使用明确且可搜索的 `x-hat` 或 `hat(x)`，并说明与原符号的对应；
- 若希腊字母在目标字体的文本层产生 NUL，先尝试正确字体映射；必要时使用 `lambda`、`tau` 等等义记法，并注明替换且保留精确原符号的可核查来源。

从最终 PDF 重新抽取全部译文页文本。出现以下任一内容即为硬失败：NUL (`U+0000`)、替换字符 (`U+FFFD`)、字面上下标标签、已知内部占位符或乱码。对连字、组合音标、箭头、数学运算符和私用区字符逐项核查来源与字体映射；禁止对全文执行 NFKD 后删除组合字符、全局替换下划线或把未知符号替换为 `[symbol]`。这些做法会悄悄改变变量、音标、标识符或数学含义。仅对已验证的局部等义映射进行转换，不保留“视觉似乎正常、文本层已损坏”的字形。

算法框内的流对象必须单独构造。不要把同一个 Flowable/Paragraph 实例同时追加到算法容器和正文 story，也不要复用带父容器、锚点或 bbox 状态的对象列表。若实现中有对象缓存或样式克隆，检查对象身份与父级归属，确保正文流对象不指向算法框；样式可以共享不可变配置，内容对象不能共享可变布局状态。

## 图、表和裁切边界

不得仅依据 `get_image_info()` 返回的大图 bbox 判定表格范围：论文中的复合图、整页面板和背景图可能吞并同页表格。表格候选应结合表题锚点、文本块、线条/单元格检测和页面渲染确认。

- 图像 bbox 与表题、表格文本或另一图号发生重叠时，视为歧义，不得按该 bbox 直接裁切；优先拆分候选区域，无法稳定拆分则保留整张原页。
- 表格裁切必须包含表题、全部行列、表注和必要边框，并留出适度外边距。宽块阈值和 y 方向裁点只能用于提出候选，不能作为最终边界。
- 对每个裁切结果单独渲染检查四边；文字或线条紧贴边缘、首末行缺失、表注消失、图号串入或面板覆盖都必须回退重算。
- 若译稿采用“译文 + 完整原页附录”，附录页应直接复制源 PDF 页面内容流，不经过截图、bbox 裁切或重新编码；合并后核对源页数量和对应页面内容。

## 分页和流式布局

删除文本抽取产生的页首页尾孤立页码，避免它单独占据一页。显式分页应使用“当前页非空才分页”的语义，或在布局后检测页内仅有页眉/页脚/页码的近空白页。不要只依赖 PDF 总页数判断无空白页。

## 验证与交付门槛

交付前完成内容、文本层与视觉三类检查：

- 对照原文核查标题层级、段落顺序、图表/公式编号、引用和附录是否齐全；
- 抽查术语在摘要、方法、结果和图注中的一致性；
- 核对关键数值、单位、正负号、小数点和统计符号；
- 从生成 PDF 重新提取全部译文页文本，确认中文可搜索，并扫描 NUL、替换字符、字面标记和乱码；
- 把最终 PDF 的每一页渲染成图，确认渲染页数与 PDF 页数一致；联系表仅用于导航和整体布局检查，不能代替以正文可读的尺寸逐页打开渲染图；需要时使用 150–200 DPI 渲染并放大，不得只抽查代表页；
- 对所有页面检查空白/近空白、裁切、重叠、字体缺失、正文过细、边缘贴字和行内大空隙；特别检查中英交界处、模型版本、数字/百分数、上标引用和列表首行。自动阈值只负责提示，必须结合视觉复核；
- 使用字符坐标检查同一逻辑行内相邻可见字形的距离，不能仅依赖抽取文本中的空格数。真实分栏、表格列间距不能直接视为正文异常；但表格各单元格内部仍须检查；
- 重点放大检查每个算法框、公式密集页、图表同页区域、宽表、跨页表和附录边界；
- 执行内联记法回归样例，确认正文与算法样式均通过；
- 若附有完整原页，核对附录页数、顺序和源页面内容流一致；
- 若发现问题，修正并重新验证，而不是仅在交付时声明缺陷。

以下情况不得交付为最终版：存在空白或近空白异常页；任何页未完成视觉复核；正文或单元格存在未解释的大空隙、异常细字；文本层含 NUL/字面标签；算法对象串入正文；表格或图像边界存在未解决歧义；附录缺页或源页面被裁切。修复后必须重新生成最终文件并从头执行上述检查，旧版渲染结果不能作为新版证据。受迭代次数或时间限制未完成逐页检查时，明确标为未验收草稿，不能以“已渲染全部页面”代替“已逐页检查”。

可使用 [`../scripts/validate_translation_pdf.py`](../scripts/validate_translation_pdf.py) 执行确定性预检。例如：

```bash
python scripts/validate_translation_pdf.py final.pdf \
  --source-pdf original.pdf \
  --pdftoppm /path/to/pdftoppm \
  --dpi 150 \
  --audit-dir /fresh/path/final-audit
```

依赖 `pypdf`、`pdfplumber`、`Pillow` 和 Poppler 的 `pdftoppm`；生成样式和回归测试另需 `reportlab` 及静态中文 TrueType 字体。优先使用环境已有依赖。

脚本会扫描译文文本层及字符坐标、检查大空隙和大面积 Thin/ExtraLight 等字重、渲染每一页、生成 3×3 联系表、报告近空白页和边缘风险，并在提供源 PDF 时核对附录页面内容流。`layout.findings` 提供页码、行文本、bbox 和间距；`layout.thin_body_fonts` 提供可疑嵌入字体。异常间距或纤细正文字体使预检返回非零，不能因文本层正常而忽略。返回零仅代表自动检查未发现所覆盖的问题，不代表排版验收完成。

有线表格按单元格检查；无框表、分栏、复杂示意图可能出现误报。只在对照实际渲染图确认是刻意布局后，用 `--layout-exclusions reviewed-regions.json` 提供局部区域列表，例如 `[{"page": 2, "bbox": [60, 90, 250, 160], "reason": "已查看该区域，为两列独立图例"}]`。坐标单位为 PDF 点，原点在页面左上角。不得整体排除正文页、放宽阈值或排除整张表来消除真实排版错误；只排除已确认的独立局部对象。

`audit.json` 中的 `manual_review_required: true` 不能被自动结果覆盖：执行者仍须实际逐页打开可读尺寸的渲染图，确认正文、算法、公式、表格、图像和分页，并简短记录各页结论及异常处理。内容流相同不保证字体资源、页面框或最终视觉完全相同，附录同样需要视觉检查。审计目录必须是新目录，避免旧渲染页混入新版结果。

修改排版 helper 或检查脚本后，运行 `python -m unittest discover -s scripts -p 'test_*.py' -v`。测试通过内存中的实际 PDF 复现旧英文断词/两端对齐失败，同时测试新正文、不同段落角色、正常表格、错误表格单元格、列表和标识符保真。Windows 默认使用微软雅黑；其他环境通过 `CJK_TEST_FONT` 指定 ReportLab 支持的静态中文 TrueType 字体。不能跳过负例，只验证“新文件能生成”。

最终提供译稿 PDF 的可访问文件链接，并简要说明采用的论文版本、译稿是否包含全部附录，以及仍存在的任何可验证限制。随后继续执行论文讲解流程。
