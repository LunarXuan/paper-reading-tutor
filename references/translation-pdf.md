# 简体中文全文译稿 PDF

仅当用户需要译稿时读取并执行本流程。目标是生成一份内容完整、术语准确、可检索且可核验的中文 PDF；不承诺逐像素复制原排版，但要保留论文结构和图表对应关系。

## 翻译范围与保真

默认翻译题名、摘要、关键词、正文标题与正文、图注、表题与表内自然语言、脚注、致谢和附录。参考文献的作者、出处、卷期页码、DOI、URL 和正式题名通常保持原文，以免破坏检索；若理解需要，可在不改动原条目的前提下补充中文题名。

保持以下内容不变：

- 公式、变量、上下标、编号和数学关系；
- 图像本身、表格数值、单位、引用编号及交叉引用；
- 代码、命令、文件名、数据集名、模型名和 URL；
- 人名、机构名及尚无稳定中文译法的专名，必要时加中文说明而非强译。

不要删减、扩写、润色成新观点，或用讲解替代翻译。原文疑似有误时忠实翻译，并用清楚标记的译者注说明，不暗中修正。

## 术语策略

开始全文翻译前先识别论文领域、子领域及核心术语，建立轻量术语表。术语选择按以下优先级判断：

1. 该专业领域通行的简体中文译法；
2. 权威教材、标准、专业学会或高质量中文论文中的稳定用法；
3. 结合定义、公式和上下文得到的准确直译。

首次出现时采用“中文（English）”，之后保持一致。一个英文词在不同上下文含义不同时允许采用不同译法，但要避免无理由漂移。对没有公认译法、直译易误导或作为技术品牌使用的词，保留英文并给出简短解释。

机器学习、统计、医学、生物学、物理等领域的近义术语不可凭日常含义替换。遇到影响方法或结论理解的歧义，查阅权威来源验证；仍不能确定时保留英文并注明。

## 版面重建

优先使用能稳定生成 Unicode 中文和嵌入字体的文档/PDF 工具。译稿应包含：

- 清晰的中文题名和原文身份信息；
- 可辨认的章节层级、段落、列表和页码；
- 原图，及与正文一致的图号和中文图注；
- 可读的表格；必要时因宽度改为横向页，但不截断数值；
- 字体清晰的公式及原编号；
- 可点击或至少可识别的 DOI/URL（工具支持时）。

若无法在合理时间内精确复刻双栏版式，可采用结构清楚的单栏译稿。优先保证内容完整、公式图表清晰和交叉引用正确，而非追求外观复制。

扫描 PDF 应先 OCR，并抽查容易误识别的符号、上下标、负号、希腊字母、表格小数点和参考文献编号。OCR 质量不足以可靠翻译时，说明受影响页码并请求更清晰文件。

## 算法、公式与文本层的安全流水线

算法行、公式说明和普通正文必须共用同一套安全的内联记法处理，不得让算法框绕过验证。若渲染器以 HTML/XML 风格标签表达上下标，处理顺序固定为：

1. 从未转义的原始文本识别受支持的记法，并转换为受控的内部 `<sub>`/`<super>` 标记；
2. 对整段文本执行转义；
3. 仅反向恢复精确匹配的白名单 `<sub>`、`</sub>`、`<super>`、`</super>`；
4. 再交给段落或算法行渲染器。

禁止在转义之后再运行会生成标签的转换函数；否则 `<sub>` 会进入文本层并显示为字面量。也禁止为了恢复下标而解码任意 HTML，这会把源论文文本当成可执行标记。算法行和正文都必须调用同一个白名单入口。

每次新增或修改 PDF 生成器后，至少用以下样例同时测试正文样式和算法样式：`q_i(x3)`、`λ_i(x1)`、`x_0`、`x₀`、`x̂`、`R_succ`。同时检查渲染图和重新提取的文本：

- 下标必须在视觉上真正降低，不能出现字面 `<sub>`、`&lt;sub&gt;` 或内部占位符；
- `x₀` 应转成真正下标；
- 组合字符 `x̂` 只有在目标字体的渲染和 ToUnicode 文本映射都正确时才可保留，否则使用明确且可搜索的 `x-hat` 或 `hat(x)`；
- 若希腊字母在目标字体的文本层产生 NUL，可使用 `lambda`、`tau` 等稳定记法，并在所附原页保留精确原符号。

从最终 PDF 重新抽取全部译文页文本。出现以下任一内容即为硬失败：NUL (`U+0000`)、替换字符 (`U+FFFD`)、字面上下标标签、已知内部占位符或乱码。对连字、组合音标、箭头、数学运算符和私用区字符做兼容归一化；无法可靠映射时使用可搜索的文字记法，不要保留“视觉似乎正常、文本层已损坏”的字形。

算法框内的流对象必须单独构造。不要把同一个 Flowable/Paragraph 实例同时追加到算法容器和正文 story，也不要复用带父容器、锚点或 bbox 状态的对象列表。若实现中有对象缓存或样式克隆，检查对象身份与父级归属，确保正文流对象不指向算法框；样式可以共享不可变配置，内容对象不能共享可变布局状态。

## 图、表和裁切边界

不得仅依据 `get_image_info()` 返回的大图 bbox 判定表格范围：论文中的复合图、整页面板和背景图可能吞并同页表格。表格候选应结合表题锚点、文本块、线条/单元格检测和页面渲染确认。

- 图像 bbox 与表题、表格文本或另一图号发生重叠时，视为歧义，不得按该 bbox 直接裁切；优先拆分候选区域，无法稳定拆分则保留整张原页。
- 表格裁切必须包含表题、全部行列、表注和必要边框，并留出适度外边距。宽块阈值和 y 方向裁点只能用于提出候选，不能作为最终边界。
- 对每个裁切结果单独渲染检查四边；文字或线条紧贴边缘、首末行缺失、表注消失、图号串入或面板覆盖都必须回退重算。
- 若译稿采用“译文 + 完整原页附录”，附录页应直接复制源 PDF 页面内容流，不经过截图、bbox 裁切或重新编码；合并后核对源页数量和对应页面内容。

## 分页和流式布局

删除文本抽取产生的页首页尾孤立页码，避免它单独占据一页。显式分页应使用“当前页非空才分页”的语义，或在布局后检测页内仅有页眉/页脚/页码的近空白页。不要只依赖 PDF 总页数判断无空白页。

## 验证与交付门槛

交付前完成内容、文本层与视觉三类检查：

- 对照原文核查标题层级、段落顺序、图表/公式编号、引用和附录是否齐全；
- 抽查术语在摘要、方法、结果和图注中的一致性；
- 核对关键数值、单位、正负号、小数点和统计符号；
- 从生成 PDF 重新提取全部译文页文本，确认中文可搜索，并扫描 NUL、替换字符、字面标记和乱码；
- 把最终 PDF 的每一页渲染成图，确认渲染页数与 PDF 页数一致；制作分批联系表或逐页翻看，不得只抽查代表页；
- 对所有页面检查空白/近空白、裁切、重叠、字体缺失和边缘贴字；自动阈值只负责提示，必须结合视觉复核；
- 重点放大检查每个算法框、公式密集页、图表同页区域、宽表、跨页表和附录边界；
- 执行内联记法回归样例，确认正文与算法样式均通过；
- 若附有完整原页，核对附录页数、顺序和源页面内容流一致；
- 若发现问题，修正并重新验证，而不是仅在交付时声明缺陷。

以下情况不得交付为最终版：存在空白或近空白异常页；任何页未完成视觉复核；文本层含 NUL/字面标签；算法对象串入正文；表格或图像边界存在未解决歧义；附录缺页或源页面被裁切。修复后必须重新生成最终文件并从头执行上述检查，旧版渲染结果不能作为新版证据。

可使用 [`../scripts/validate_translation_pdf.py`](../scripts/validate_translation_pdf.py) 执行确定性预检。例如：

```bash
python scripts/validate_translation_pdf.py final.pdf \
  --source-pdf original.pdf \
  --pdftoppm /path/to/pdftoppm \
  --audit-dir /fresh/path/final-audit
```

脚本会扫描译文文本层、渲染每一页、生成联系表、报告近空白页和边缘风险，并在提供源 PDF 时核对附录页面内容流。`audit.json` 中的 `manual_review_required: true` 不能被自动结果覆盖：执行者仍须实际打开全部联系表，逐页确认算法、公式、表格、图像和分页。审计目录必须是新目录，避免旧渲染页混入新版结果。

最终提供译稿 PDF 的可访问文件链接，并简要说明采用的论文版本、译稿是否包含全部附录，以及仍存在的任何可验证限制。随后继续执行论文讲解流程。
